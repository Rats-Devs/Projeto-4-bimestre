2: O que é uma origem (origin)?

para entender CORS precisa-se entender o conceito de origem
uma origem é composta por 3 elementos:
-Protocolo: http ou https
-Host: domínio ou endereço, como localhost
-Porta: número usado para acessar o serviço

3: O que é CORS?
CORS significa Cross-Origin Resource SHaring, compartilhamento de recursos
entre origens diferentes

O CORS é um mecanismo de segurança dos navegadores. Controla se um site pode
ler respostas de uma API que está em outra origem

O JavaScript do Cinemax solicita os filmes à API
A API recebe a solicitação e pode processá-la
O navegador verifica se a resposta pode ser compartilhada com a origem do site
Se a API não autorizar essa origem por meio do CORS, o navegador pode bloquear o acesso do JavaScript à resposta

o CORS não conecta a API ao MySQL e não substitui autenticação. Ele Controla
o compartilhamento de respostas entre origens no navegador

explicação
↓

builder.Services.AddCors(options =>
    builder: objeto que prepara a aplicação antes da construção
    services: coleção dos serviços que a aplicação vai utilizar
    addCors: registra os serviços e confugirações necessárias para trabalhar com CORS

options => 
    é uma lambda(função anonima usada para criar árvores de expressão de forma rápida e limpa) do C#
    ela permite passar uma função como argumento. Está fornecendo instruções para configurar o CORS

    O parâmetro options representa as opções de configuração do CORS. 

{
    options.AddPolicy("SiteCinemax", policy =>
        AddPolicy cria uma política de CORS com o nome SiteCinemax
        uma política é um conjunto de regras que determina quais origens, headers e métodos serão permitidos
    {
        policy
                o segundo parâmetro é outra lambda. policy representa a politica que estamos configurando
            .AllowAnyOrigin()
                permite que qualquer origem seja aceita por essa política
            .AllowAnyHeader()
                permite diferentes headers(cabeçalhos) HTTP nas requisições que seguem a política
            .AllowAnyMethod();
                Permite os métodos HTTP:
                -GET: consultar dados.
                -POST: cadastrar dados.
                -PUT: atualizar dados.
                -DELETE: excluir dados.          
    });
});

5:existem duas etapas e por que?

primeira etapa registra e configura a política
    builder.Services.AddCors(...); <- define as regras e damos o nome SiteCinemax à política

segunda etapa ativa a política na aplicação
    quando a aplicação já estiver sendo construida essa linha será adicionada depois. Ela faz com que
    a política seja aplicada no processamento das requisições

6: oq o CORS não resolve?

mesmo com o CORS configurado, podemos encontrar outros problemas:
a API não está em execução
endedreço ou porta da API estão incorretos
URL da imagem nao existe
etc.

ainda no program.cs embaixo de app.UseHttpsRedirection();
adicionei:
app.UseCors("SiteCinemax");

colocamos aqui pq o
UseHttpsRedirection() trata o redirecionamento para HTTPS.
UseCors("SiteCinemax") aplica a política de CORS que configuramos.
UseAuthorization() trata a autorização das requisições.
